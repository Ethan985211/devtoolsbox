使用方法

1选择 UUID 版本：v4（纯随机，最常用）或 v1（基于时间戳+MAC地址）
2设置是否需要大写，以及批量生成的数量（1-100个）
3点击"生成 UUID"按钮，下方立即显示生成的 UUID 列表
4点击"复制全部"将结果复制到剪贴板，每个 UUID 一行，方便粘贴使用

使用技巧

💡UUID v4 完全随机，适合绝大多数场景（数据库主键、文件标识、令牌等）。单个 v4 UUID 的碰撞概率极低，可放心使用。
💡UUID v1 基于时间戳和节点信息生成，具有时间排序特性。适合需要按时间排序的场景，但会暴露生成时间和机器信息，注意隐私。
💡批量生成时，v1 UUID 在同一毫秒内会使用时钟序列递增，确保唯一性。v4 则完全独立随机生成。

常见问题

UUID v4 和 v1 有什么区别？
v4 基于随机数生成，共 122 位随机位，碰撞概率极低（需生成约 2.71×10¹⁸ 个才有 50% 碰撞概率）。v1 基于时间戳（100纳秒精度）和节点标识（通常是 MAC 地址），保证时空唯一性，可通过时间排序。
UUID 作为数据库主键有什么优缺点？
优点：全局唯一，分布式系统友好，无需中心化ID分配器。缺点：UUID v4 随机无序会导致 B+树索引碎片化，写入性能下降。如果使用 UUID 作主键，建议使用有序版本（v1 或 v7）或使用自增整数主键+UUID 业务键的组合。
生成的 UUID 是否真的唯一？
v4 UUID 的随机位有 122 位，理论上需要生成数十亿亿个才有极小碰撞概率。v1 保证时空唯一（同一节点同一时刻通过时钟序列区分）。本工具 v4 使用浏览器 crypto.randomUUID() 标准 API，v1 使用 crypto.getRandomValues() 模拟实现。
